# Аудит і очищення місця на диску (Windows + WSL2 + Docker Desktop)

Твоя роль — **розвідка й план, а не прибирання**. Аналізуєш лише читанням, звітуєш і готуєш
точні команди та скрипти. Усе, що видаляє дані, зупиняє WSL або потребує прав адміністратора,
запускає сам користувач.

Чому так:
- Користувач прямо просив нічого не видаляти самостійно. Ціна помилки (знести проєкт із
  незапушеними комітами чи іменований docker-том із базою) незрівнянна з виграшем у кілька ГБ.
- `wsl --shutdown` і стискання VHDX обривають Docker, підключення IDE й термінали, а заразом
  можуть убити середовище, через яке працює сама сесія.
- `Optimize-VHD` і `vssadmin` потребують прав адміністратора, яких сесія не має.

Якщо користувач прямо просить виконати одну конкретну команду очищення кешу — скажи, що саме
вона видалить, і виконуй лише її. Ніколи не виконуй сам: очищення кошика, видалення папок
проєктів, `docker volume prune -a`, `docker system prune --volumes`, `wsl --unregister`.

## Перед початком

1. Прочитай `references/machine-notes.md` — там шляхи до VHDX, попередній baseline і відомі
   пастки цієї машини. Факти могли застаріти: перевіряй те, на що спираєшся.
2. Середовище: Bash-інструмент — це Git Bash на Windows. Команди всередині WSL запускай через
   `wsl.exe -e bash -ic '...'` (саме `-ic`: nvm/node підвантажуються лише з `.bashrc`).
3. Скрипти скіла лежать у `scripts/` у базовій директорії скіла (її шлях показано під час
   завантаження скіла). PowerShell-скрипти запускай за повним Windows-шляхом. Для `.sh` із WSL
   переведи шлях: `C:\Users\...` → `/mnt/c/Users/...` (або `wslpath -u '<шлях>'` усередині WSL).
4. Скани, що тривають довше ~2 хвилин, запускай у фоні й коротко повідомляй користувачу, що
   зараз відбувається. Не використовуй `Get-ChildItem -Recurse -Include` по всьому диску — на
   200 ГБ це понад 10 хвилин; бери скрипти нижче, вони обходять дерево через .NET.
5. Кожен виклик `wsl.exe` знову запускає ВМ WSL. Якщо користувач саме готується стискати VHDX,
   не запускай команди в WSL або попередь, що після них знову потрібен `wsl --shutdown`.

## Порядок аудиту

Іди згори донизу й зупиняйся, коли картина ясна: мета — знайти великі шматки, а не описати
кожен мегабайт.

1. **Томи.** `Get-Volume` і `Get-PSDrive -PSProvider FileSystem`. Літера, якої немає в
   `Get-Volume`, — віртуальний диск (наприклад, G: — Google Drive у режимі стримінгу). Це не
   місце, куди можна перенести VHDX.
2. **Корінь диска.** `scripts/dirsizes.ps1 -Root D:\`. Порівняй суму зі значенням Used тому:
   різниця зазвичай сидить у `System Volume Information` (тіньові копії, точки відновлення).
   Перевірити це може лише адмін: `vssadmin list shadowstorage /for=D:`.
3. **Заглиблення.** Той самий скрипт для папок, що займають понад ~5% диска.
4. **VHDX.** Дистрибутиви WSL: `HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss` →
   `BasePath\ext4.vhdx`. Диск даних Docker Desktop: `<BasePath docker-desktop>\..\disk\docker_data.vhdx`.
   Порівняй розмір файлу з реальною зайнятістю всередині (`df -h /` у дистрибутиві,
   `docker system df` для Docker). Різниця — те, що поверне саме лише стискання. VHDX сам не
   зменшується, коли всередині щось видалили, — це головне джерело «зниклого» місця.
5. **Усередині WSL.** `scripts/wsl-usage.sh` — df, домашній каталог, `~/.cache`, Docker
   (образи, томи з розбивкою на анонімні та іменовані, build cache).
6. **Відновлювані залежності.** `scripts/find-deps-dirs.ps1 -Roots <папки>` — node_modules,
   vendor, .venv. Видаляти безпечно, лише якщо в проєкті є lock-файл або requirements.
7. **Старі проєкти.** `scripts/repo-audit.ps1 -Root <папка> [-CompareWith <папка-двійник>] -Csv <файл>`.
   Вердикт `safe` означає, що код повністю на remote, але gitignored-файли (`.env`, локальні
   дампи) у git не потрапляють: колонка `HasEnv` підказує, де їх варто зберегти окремо.
   Не пропонуй видаляти проєкт із `local-work` — там незакомічені зміни, незапушені коміти,
   stash або немає remote.
8. **Кошик.** Розміри за SID у `<диск>:\$RECYCLE.BIN`, порівняй із `whoami /user`. Чужі SID —
   від старих інсталяцій Windows: у кошику користувача їх не видно, і звичайне очищення кошика
   їх не зачепить.

## Формат звіту

Пиши мовою, якою спілкується користувач, коротко. Структура:

1. Один рядок: скільки вільно зі скількох і що загалом з'їдає місце.
2. Таблиця: **Що | Розмір | Можна повернути | Ризик / умова**. Числа бери зі сканів; оцінки
   позначай `~`.
3. Кроки від безпечних до спірних. Кожна команда — в окремому блоці коду, з поясненням, що
   вона видалить. Скрипти для користувача називай повним шляхом.
4. Що не перевірено й чому (немає прав адміна, скан перервано тощо).

## Типові дії (готує Claude, запускає користувач)

**Кеші та Docker усередині WSL** — `scripts/cleanup-wsl.sh`. Інтерактивний: показує розмір
кожного пункту й питає `[y/N]`. Охоплює кеші yarn/npm/composer/apt, кеші JetBrains і браузерів
для playwright/puppeteer, `docker builder prune -a`, `docker image prune -a`,
`docker volume prune` (у Docker ≥ 23 видаляє лише анонімні томи) і наприкінці `fstrim`.
Запуск у терміналі WSL:
```bash
bash /mnt/c/<шлях-до-скіла>/scripts/cleanup-wsl.sh
```
Іменовані томи (`*_mysql-data`, `*_db_data` тощо) користувач переглядає й видаляє вручну:
у них можуть бути живі бази.

**Стискання VHDX** — `scripts/compact-vhdx.ps1`, лише в PowerShell **від адміністратора**.
Скрипт сам знаходить VHDX дистрибутивів і Docker, перевіряє, що Docker Desktop закрито, робить
`fstrim`, `wsl --shutdown`, чекає повної зупинки ВМ, стискає кожен диск і друкує розміри до й
після. Якщо модуля Hyper-V немає, перемикається на diskpart.

**Sparse VHD** (`wsl --manage <distro> --set-sparse true`) — автостискання, але Microsoft сама
попереджає про ризик пошкодження диска. Не пропонуй за замовчуванням; якщо користувач хоче —
лише за зупиненої WSL і після свіжого `wsl --export`.

## Пастки

- **`Optimize-VHD` → 0x80070020 (файл зайнятий).** ВМ WSL ще жива. Її піднімає будь-який
  клієнт `wsl.exe`: Docker Desktop (закривати через трей → Quit, а не хрестиком), WSL-термінали,
  IDE (PhpStorm / VS Code remote), Codex. Після `wsl --shutdown` перевір `wsl -l -v` (усі
  `Stopped`) і зачекай 5–10 секунд. `compact-vhdx.ps1` показує, які процеси тримають WSL.
- **git: «detected dubious ownership».** Файли належать SID старої інсталяції Windows. Для
  читання використовуй `git -c safe.directory=* ...`; глобальний конфіг не чіпай.
- **Кількість Dirty у Windows-git завищена** на репозиторіях, створених у WSL або з іншими
  налаштуваннями CRLF/filemode. Кажи про це, коли наводиш цифри.
- **`wsl.exe -l -v` і `wsl --version` виводять UTF-16.** У PowerShell текст читається з
  пробілами між літерами; у Git Bash виглядає як сміття. Читати треба з PowerShell.
- **`docker volume prune -a`** видаляє й іменовані томи — не пропонуй без списку томів.
- **Перенесення VHDX на інший диск** має сенс, лише якщо там справді є місце і це локальний
  том (не Google Drive).
