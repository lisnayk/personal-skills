# Аудит и очистка места на диске (Windows + WSL2 + Docker Desktop)

Твоя роль — **разведка и план, а не уборка**. Анализируешь только чтением, даёшь отчёт и
готовишь точные команды и скрипты. Всё, что удаляет данные, останавливает WSL или требует
прав администратора, запускает сам пользователь.

Почему так:
- Пользователь прямо просил ничего не удалять самостоятельно. Цена ошибки (снести проект с
  незапушенными коммитами или именованный docker-том с базой) несравнима с выигрышем в пару ГБ.
- `wsl --shutdown` и сжатие VHDX рвут Docker, IDE-подключения и терминалы, а заодно могут
  убить окружение, через которое работает сама сессия.
- `Optimize-VHD` и `vssadmin` требуют прав администратора, которых у сессии нет.

Если пользователь прямо просит выполнить одну конкретную команду очистки кэша — назови, что
именно она удалит, и выполняй только её. Никогда не выполняй сам: очистку корзины, удаление
папок проектов, `docker volume prune -a`, `docker system prune --volumes`, `wsl --unregister`.

## Перед началом

1. Прочитай `references/machine-notes.md` — там пути к VHDX, прошлый baseline и известные
   ловушки этой машины. Факты могли устареть: перепроверяй то, на что опираешься.
2. Окружение: Bash-инструмент — это Git Bash на Windows. Команды внутри WSL запускай через
   `wsl.exe -e bash -ic '...'` (именно `-ic`: nvm/node подгружаются только из `.bashrc`).
3. Скрипты скила лежат в `scripts/` в базовой директории скила (её путь показан при загрузке
   скила). PowerShell-скрипты запускай по полному Windows-пути. Для `.sh` из WSL переведи путь:
   `C:\Users\...` → `/mnt/c/Users/...` (или `wslpath -u '<путь>'` внутри WSL).
4. Сканы, которые идут дольше ~2 минут, запускай в фоне и коротко сообщай пользователю, что
   сейчас происходит. Не используй `Get-ChildItem -Recurse -Include` по всему диску — на 200 ГБ
   это больше 10 минут; бери скрипты ниже, они обходят дерево через .NET.

## Порядок аудита

Иди сверху вниз и останавливайся, когда картина ясна: цель — найти крупные куски, а не
описать каждый мегабайт.

1. **Тома.** `Get-Volume` и `Get-PSDrive -PSProvider FileSystem`. Буква, которой нет в
   `Get-Volume`, — виртуальный диск (например, G: — Google Drive в режиме стриминга). Это не
   место, куда можно перенести VHDX.
2. **Корень диска.** `scripts/dirsizes.ps1 -Root D:\`. Сравни сумму со значением Used тома:
   разница обычно сидит в `System Volume Information` (теневые копии, точки восстановления).
   Проверить это может только админ: `vssadmin list shadowstorage /for=D:`.
3. **Углубление.** Тот же скрипт по папкам, которые занимают больше ~5% диска.
4. **VHDX.** Дистрибутивы WSL: `HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss` →
   `BasePath\ext4.vhdx`. Диск данных Docker Desktop: `<BasePath docker-desktop>\..\disk\docker_data.vhdx`.
   Сравни размер файла с реальной занятостью внутри (`df -h /` в дистрибутиве, `docker system df`
   для Docker). Разница — то, что вернёт одно только сжатие. VHDX сам не уменьшается, когда
   внутри что-то удалили, — это главный источник «пропавшего» места.
5. **Внутри WSL.** `scripts/wsl-usage.sh` — df, домашний каталог, `~/.cache`, Docker
   (образы, тома с разбивкой на анонимные и именованные, build cache).
6. **Восстановимые зависимости.** `scripts/find-deps-dirs.ps1 -Roots <папки>` — node_modules,
   vendor, .venv. Удалять безопасно, только если в проекте есть lock-файл или requirements.
7. **Старые проекты.** `scripts/repo-audit.ps1 -Root <папка> [-CompareWith <папка-двойник>] -Csv <файл>`.
   Вердикт `safe` значит, что код целиком на remote, но gitignored-файлы (`.env`, локальные дампы)
   в git не попадают: колонка `HasEnv` подсказывает, где их стоит сохранить отдельно.
   Не предлагай удалять проект с `local-work` — там незакоммиченные изменения, незапушенные
   коммиты, stash или нет remote.
8. **Корзина.** Размеры по SID в `<диск>:\$RECYCLE.BIN`, сравни с `whoami /user`. Чужие SID —
   от старых установок Windows: в корзине пользователя их не видно, и обычная очистка корзины
   их не тронет.

## Формат отчёта

Пиши по-русски, коротко. Структура:

1. Одна строка: сколько свободно из скольки и что в целом съедает место.
2. Таблица: **Что | Размер | Можно вернуть | Риск / условие**. Числа бери из сканов; оценки
   помечай `~`.
3. Шаги от безопасных к спорным. Каждая команда — в своём блоке кода, с пояснением, что она
   удалит. Скрипты для пользователя называй полным путём.
4. Что не проверено и почему (нет прав админа, скан прерван и т.п.).

## Типовые действия (готовит Claude, запускает пользователь)

**Кэши и Docker внутри WSL** — `scripts/cleanup-wsl.sh`. Интерактивный: показывает размер
каждого пункта и спрашивает `[y/N]`. Покрывает кэши yarn/npm/composer/apt, кэши JetBrains и
браузеров для playwright/puppeteer, `docker builder prune -a`, `docker image prune -a`,
`docker volume prune` (в Docker ≥ 23 удаляет только анонимные тома) и в конце `fstrim`.
Запуск в терминале WSL:
```bash
bash /mnt/c/<путь-к-скилу>/scripts/cleanup-wsl.sh
```
Именованные тома (`*_mysql-data`, `*_db_data` и т.п.) пользователь смотрит и удаляет вручную:
в них могут быть живые базы.

**Сжатие VHDX** — `scripts/compact-vhdx.ps1`, только в PowerShell **от администратора**.
Скрипт сам находит VHDX дистрибутивов и Docker, проверяет, что Docker Desktop закрыт, делает
`fstrim`, `wsl --shutdown`, ждёт полной остановки ВМ, сжимает каждый диск и печатает размеры
до и после. Если модуля Hyper-V нет, переключается на diskpart.

**Sparse VHD** (`wsl --manage <distro> --set-sparse true`) — автосжатие, но Microsoft сама
предупреждает о риске повреждения диска. Не предлагай по умолчанию; если пользователь хочет —
только при остановленном WSL и после свежего `wsl --export`.

## Ловушки

- **`Optimize-VHD` → 0x80070020 (файл занят).** ВМ WSL ещё жива. Её поднимает любой клиент
  `wsl.exe`: Docker Desktop (закрывать через трей → Quit, а не крестиком), WSL-терминалы,
  IDE (PhpStorm / VS Code remote), Codex. После `wsl --shutdown` проверь `wsl -l -v` (все
  `Stopped`) и подожди 5–10 секунд. `compact-vhdx.ps1` показывает, какие процессы держат WSL.
- **git: «detected dubious ownership».** Файлы принадлежат SID старой установки Windows. Для
  чтения используй `git -c safe.directory=* ...`; глобальный конфиг не трогай.
- **Число Dirty у Windows-git завышено** на репозиториях, созданных в WSL или с другими
  настройками CRLF/filemode. Говори об этом, когда приводишь цифры.
- **`wsl.exe -l -v` и `wsl --version` выводят UTF-16.** В PowerShell текст читается с пробелами
  между буквами; в Git Bash выглядит как мусор. Читать нужно из PowerShell.
- **`docker volume prune -a`** удаляет и именованные тома — не предлагай без списка томов.
- **Перенос VHDX на другой диск** имеет смысл, только если там реально есть место и это
  локальный том (не Google Drive).
